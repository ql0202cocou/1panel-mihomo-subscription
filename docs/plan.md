# 项目计划

本项目是一个面向 1Panel 自托管场景的 Mihomo 订阅转换与分发工具。目标是实现一个轻量级的 Sub-Store 类应用：用户在 Web 页面中录入机场订阅，配置自定义分流规则，系统处理后生成长期有效的 Mihomo 订阅链接。

## 项目定位

这是一个个人自托管应用，优先服务单用户或少量用户场景。

核心目标：

- 通过 1Panel 快速部署。
- 提供简单易用的 Web 管理页面。
- 支持录入不同来源格式的机场订阅。
- 将订阅转换为 Mihomo 可使用的配置。
- 允许用户用自定义规则替换原订阅中的分流规则。
- 允许用户向订阅中追加自定义代理分组。
- 允许用户向自定义分组中加入自己的代理节点。
- 生成长期有效、可复制到 Mihomo 客户端的订阅链接。
- 在处理外部订阅 URL 时做好基础安全防护。

项目早期不追求完整复刻 Sub-Store，而是先做一个稳定、清晰、可维护的核心版本。

## 目标用户

- 使用 1Panel 管理个人服务器的用户。
- 使用 Mihomo、Clash Meta 或兼容客户端的用户。
- 希望集中管理机场订阅和分流规则的用户。
- 希望订阅链接长期稳定，不想频繁修改客户端配置的用户。

## 核心使用流程

```text
用户打开 Web 页面
  -> 输入管理员账户和密码登录
  -> 新建订阅配置
  -> 选择原始订阅类型
  -> 填写机场订阅 URL
  -> 填写或编辑自定义分流规则
  -> 可选：添加自定义节点和自定义代理分组
  -> 保存配置
  -> 生成 Mihomo 订阅链接
  -> 将链接复制到 Mihomo 客户端
```

客户端下载生成链接时：

```text
客户端请求永久订阅链接
  -> 服务校验随机路径和 token
  -> 拉取或读取缓存中的机场订阅
  -> 追加用户自定义节点和代理分组
  -> 替换为用户配置的规则
  -> 返回 Mihomo YAML
```

## Web 页面需求

MVP 阶段需要一个可用的管理页面，不需要复杂视觉设计。

用户进入管理页面时，需要先看到登录页面。登录成功后才能查看订阅配置、修改配置、生成订阅链接或重置 token。

登录页面至少包含：

- 管理员账户输入框。
- 管理员密码输入框。
- 登录按钮。
- 登录失败提示。

管理员账户和密码不在 Web 页面内初始化。它们应通过 1Panel 应用安装参数写入 `docker-compose.yml` 环境变量。

页面采用“顶部托管链接 + Mihomo 配置结构卡片 + 底部生成配置”的形式。

整体结构：

```text
顶部：托管订阅链接区域
  - 当前托管订阅链接
  - 复制链接
  - 重置 token
  - 重置 public path
  - 最近生成时间和当前状态

中部：按 Mihomo 配置结构展示的配置卡片
  - 基础信息
  - 原始订阅源
  - 自定义节点 proxies
  - 自定义分组 proxy-groups
  - 分流规则 rules
  - 输出预览和校验结果

底部：生成配置按钮
  - 点击后先校验配置
  - 成功后弹窗展示新的托管订阅链接
  - 失败后弹窗展示具体错误
```

每个配置卡片右上角提供编辑按钮。点击编辑按钮后，通过弹窗或抽屉修改该部分配置，主页面保持为当前订阅配置总览。

页面至少包含：

- 订阅配置列表。
- 新建和编辑订阅配置。
- 订阅名称输入框。
- 原始订阅类型选择：
  - `mihomo`
  - `clash`
  - `surge`
  - `loon`
- 机场订阅 URL 输入框。
- 自定义规则编辑区域。
- 自定义节点编辑区域。
- 自定义代理分组编辑区域。
- 启用/禁用开关。
- 生成或重置订阅链接按钮。
- 复制订阅链接按钮。

卡片展示建议：

- 基础信息：配置名称、启用状态、输出类型。
- 原始订阅源：来源类型、脱敏后的订阅 URL、最近拉取状态。
- 自定义节点：节点数量、节点类型分布、最近修改时间。
- 自定义分组：分组数量、引用校验状态、重名风险提示。
- 分流规则：规则行数、引用的分组、校验状态。
- 输出预览：缓存状态、最近生成时间、YAML 校验状态。

生成配置弹窗成功状态展示：

```text
托管订阅链接已生成

https://sub.example.com/<public-path-prefix>/api/sub/<profile-token>

[复制链接] [预览配置] [关闭]
```

生成配置弹窗失败状态展示：

```text
无法生成配置

- rules 第 12 行引用了不存在的分组 `Auto`
- 自定义分组 `Proxy` 与原始订阅分组重名
```

后续可以补充：

- 规则模板。
- 规则排序。
- 订阅预览。
- 代理组预览。
- 节点可用性检查。
- 最近刷新状态。
- 最近访问时间。
- 错误诊断提示。

## 订阅转换需求

第一阶段优先支持：

```text
mihomo/clash -> mihomo
```

处理方式：

- 拉取原始订阅 YAML。
- 保留代理节点信息。
- 保留代理组信息。
- 追加用户自定义代理节点。
- 追加用户自定义代理分组。
- 允许自定义分组引用机场原有节点和用户自定义节点。
- 用用户自定义规则替换原始 `rules`。
- 输出合法的 Mihomo YAML。

自定义节点和分组处理原则：

- 自定义节点写入输出配置的 `proxies`。
- 自定义分组写入输出配置的 `proxy-groups`。
- 分组名称不能和原始订阅中的分组重名，除非用户明确选择覆盖策略。
- MVP 阶段默认采用追加策略，不自动修改原始代理组。
- 用户规则可以引用自定义分组名称。
- 如果规则引用了不存在的分组，保存或生成时需要提示错误。

后续再逐步支持：

```text
surge -> mihomo
loon -> mihomo
sing-box -> mihomo
```

不要在 MVP 阶段同时追求所有格式完整兼容。优先保证 Mihomo 输出稳定。

## 永久链接需求

生成的订阅链接需要长期有效，但必须可以主动失效。

链接格式建议：

```text
https://sub.example.com/<public-path-prefix>/api/sub/<profile-token>
```

其中：

- `PUBLIC_BASE_URL` 表示外部访问地址。
- `public-path-prefix` 是应用级随机路径前缀。
- `profile-token` 是每个订阅配置独立生成的随机 token。

需要支持：

- 复制永久订阅链接。
- 重置单个订阅配置的 token。
- 重置全局随机路径前缀。
- 禁用订阅配置后链接立即失效。

## 安全需求

本项目会保存和请求机场订阅 URL，因此安全是核心需求之一。

必须考虑：

- Web 管理页面需要管理员认证。
- 管理 API 需要认证。
- 管理员账户和密码通过 1Panel compose 环境变量配置。
- 公开订阅链接不能暴露原始机场 URL。
- 原始订阅 URL 不能完整写入日志。
- 拉取远程订阅时需要防 SSRF。
- 限制请求超时、跳转次数和响应大小。
- 对无效 public path、无效 token、禁用配置统一返回 `404`。

详细设计见：

```text
docs/security-design.md
```

## 1Panel 部署需求

项目需要维护 1Panel 应用包：

```text
apps/mihomo-subscription
```

应用包需要支持：

- 设置 Web 端口。
- 设置管理员账户。
- 设置管理员密码。
- 设置公开访问地址 `PUBLIC_BASE_URL`。
- 设置随机路径前缀 `PUBLIC_PATH_PREFIX`。
- 设置日志级别。
- 设置订阅拉取超时和最大响应大小。
- 持久化 SQLite 数据。

个人使用时先作为 1Panel 本地应用安装；后续如需分发到第三方商店，应继续遵守官方应用包结构。

## MVP 范围

第一版可交付目标：

- 1Panel 中可以安装并启动。
- Web 页面可以使用 1Panel compose 中配置的管理员账户和密码登录。
- 可以创建、编辑、删除订阅配置。
- 可以填写 `mihomo/clash` 类型订阅 URL。
- 可以填写自定义 Mihomo rules。
- 可以添加自定义 Mihomo 代理节点。
- 可以添加自定义 Mihomo 代理分组。
- 可以生成永久订阅链接。
- 客户端访问永久链接时返回处理后的 Mihomo YAML。
- 基础 SSRF 防护生效。
- 原始订阅 URL 不出现在公开输出和普通日志中。

## 暂不做

MVP 阶段暂不实现：

- 多用户权限系统。
- 团队协作。
- 复杂规则市场。
- 完整 Sub-Store 功能兼容。
- 所有订阅格式互转。
- 复杂节点测速和自动选择策略。
- 批量节点导入导出。
- 云端同步。
- 多实例部署。
- 高级审计系统。

这些能力可以在核心流程稳定后再评估。

## 阶段计划

### 阶段一：核心闭环

- 搭建 Web 管理页面。
- 将现有订阅 CRUD 调整为 profile 管理。
- 实现 `mihomo/clash -> mihomo` 规则替换。
- 实现自定义节点追加。
- 实现自定义代理分组追加。
- 生成永久订阅链接。
- 支持 SQLite 持久化。

### 阶段二：安全和部署

- 增加管理员认证。
- 增加 SSRF 防护。
- 增加请求大小、超时和跳转限制。
- 增加缓存机制。
- 完善 1Panel 应用安装参数。

### 阶段三：体验优化

- 增加规则预览。
- 增加自定义节点和代理组预览。
- 增加订阅刷新状态。
- 增加错误提示。
- 增加 token 重置和 public path 重置入口。
- 优化移动端管理体验。

### 阶段四：格式扩展

- 支持 `surge -> mihomo`。
- 支持 `loon -> mihomo`。
- 评估是否支持 `sing-box -> mihomo`。

## 成功标准

项目达到可用状态时，应满足：

- 用户可以在 1Panel 中完成部署。
- 用户可以通过 Web 页面完成订阅配置。
- 生成链接可以直接用于 Mihomo 客户端。
- 用户可以追加自己的代理节点和代理分组。
- 用户规则可以引用自定义代理分组。
- 链接长期有效，并可手动重置。
- 服务不会把原始机场订阅 URL 暴露给客户端。
- 常见 SSRF 风险有基础防护。
- 项目结构清晰，方便后续继续扩展。
